# POPLAR AGENCY — COUNCIL VERDICT (adversarial-substantive)

**Verification record:** all seven artifacts read in full; consistency cross-checked. Found: one duplicate listing, one orphaned state machine, two cross-doc contradictions.

## (a) KERNEL-SPLIT VERDICT — APPROVED WITH MOVES
The split is sound; "agent never self-approves" is the correct spine. But "auto" is safe only under three conditions the registry must state in §0: (1) reversible or purely internal effect, (2) deterministic run-time verification, (3) failure = quarantine + escalation, never retry.
- **K-OPE-004 (redemption validation) → auto-with-hold-on-signal.** A validated redemption is a binding merchant obligation (honor-at-validation). Auto-approving past a fraud/velocity flag commits merchant money. Any K-OPE-002 flag or over-velocity → `held`, resolved at daily review. Deferral is lossless; approval is not.
- **K-OPE-003 (daily review): safe only with** explicit per-exception ack (logged), aging escalation (unacked 24h → page), severity-tiered SLA — fraud-critical signals page immediately, never at daily cadence. Ban tacit-consent timeouts ("unacted = acknowledged" = silent self-approval).
- **ADD K-OPE-006 consent withdrawal & suppression — AUTO, the one case where auto is legally mandated** (GDPR Art. 7(3) "without undue delay"; CCPA opt-out ≤15 days; withdrawal as easy as grant). Purely subtractive; verification = suppression confirmed in all outbound audiences; failure escalates.
- **ADD K-APP-004 campaign amendment** (mid-flight offer/budget changes): HUMAN — post-freeze change control is the classic merchant-dispute surface.
- **ADD K-REC-003 redemption void/refund: HUMAN.** `redemptions.state(active,void,refunded)` exists but no kernel owns those transitions — an orphaned financial state machine.
- K-LEA-001: auto-**draft** only; distribution human-released (state explicitly).
- K-DES-002 sits in BOTH human-gated and draft-only lists — resolve to draft-only + human release; categories must be mutually exclusive.
- K-REC-001 stays human-gated: daemon matches deterministically, human adjudicates exceptions.

## (b) DATA-CONTRACT VERDICT — SOUND SPINE, FIVE GAPS
Events-as-single-source-of-truth is correct; passport-as-projection matches the boundary. But stateful tables must be declared **projections** — redemptions.state, consents, communications.status change only via new events, never UPDATE — or the spine rots. Amendments:
- **ADD `exceptions` table** (kernel_run_id, severity, status open/ack/resolved, operator, decision, ts) — the audit spine of "daemon never self-approves" has no entity today.
- **ADD `campaign_briefs`** (versioned, content_hash, approval_evidence): a `version int` cannot prove what was frozen; freeze = hash-pinned snapshot.
- **ADD `campaign_templates`** (FR-104 referenced everywhere, defined nowhere).
- **ADD `users.merchant_id`** (nullable): a merchant_champion with only organization_id can see every merchant — a schema-level tenant hole.
- **`consents.purpose`: add `fraud_prevention`** — `events.device_risk` is collected under purposes that don't cover it (GDPR purpose limitation). State per-purpose withdrawal rows; processor disclosure rides in notice_version + evidence.
- `gross_sale_band`: OK for v1, but reports may never sum bands into pseudo-totals.
- Economics is triplicated (budget / margin_model / economics): offers.margin_model is the binding margin contract; the merchant-approved snapshot lives in campaign_merchants.economics. State precedence.
- Billing: no invoice/subscription entity — declare out-of-v1-scope explicitly; silent gaps become scope disputes.
